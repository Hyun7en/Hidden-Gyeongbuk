# ADR-002 · 프론트엔드 = React SPA (Vite·TS)

**상태** Accepted  
**작성일자** 2026-05-29

## 컨텍스트

단독 풀스택 개발이며, 코스 공유 URL·PWA 요구가 있다. 백엔드는 Java(타입 언어)이고 API 응답 스키마가 명세서에 정의돼 있다.

## 결정

REST API + React SPA 구조. 빌드·언어는 Vite + TypeScript. 백엔드 개발자(본인)가 프론트도 직접 개발하고, 정적 번들은 백엔드에서 서빙한다.

## 근거

SPA가 코스 공유 URL(FR-C-06)·PWA에 유리하고 백엔드와 분리가 명확하다. TypeScript로 API 응답 타입을 명세서 스키마와 맞춰 런타임 오류를 줄인다. Vite는 현재 React 표준 빌드 도구.

## 결과

단독 개발이라 프론트 학습·작업 시간을 일정에 반영한다(ADR-011). 프론트 본격 개발은 P3. 프론트/백엔드를 한 모노리포로 관리.

## 대안

①CRA — 유지보수 사실상 중단·느림 ②Vue/Svelte — React 대비 생태계·자료 열세 ③순수 JS — API 연동이 많아 타입 안정성 손해 ④서버사이드 렌더링(Thymeleaf) — SPA의 공유 URL·PWA 이점 상실. → Vite+React+TS 선택.

## 후속 주석

**2026-08-08** — 본 ADR이 SPA 선택 근거로 든 "PWA 요구"는 ADR-022에서 폐기됐다(FR-W-04 삭제). 다만 **결론은 그대로 유효하다** — 코스 공유 URL(FR-C-06)과 TypeScript 타입 안정성이라는 나머지 근거만으로도 React SPA 선택은 성립한다. 대안 ④의 "PWA 이점 상실" 부분도 마찬가지로 무효하나, 공유 URL 이점은 유지된다.
