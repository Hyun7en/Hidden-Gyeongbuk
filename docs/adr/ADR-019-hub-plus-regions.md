# ADR-019 · 추천 범위 = 거점 필수 + 지역 다중선택(옵션), 홈은 지역 카탈로그

**상태** Accepted  
**작성일자** 2026-07-30

## 컨텍스트

기존 화면 설계는 홈을 추천/지역 두 경로의 대등한 분기점으로 두고, 추천은 거점(Hub)에서 출발해 여러 지역을 넘나드는 코스를 짜는 방식이었다. 검토 결과 두 가지 개선이 필요했다. (1) 사용자가 특정 지역을 집중해서 보고 싶은 수요(예: 안동만 제대로)를 기존 구조가 담지 못했다 — 추천은 항상 거점 주변 전체에서 짜였다. (2) 홈이 추상적인 진입 카드 둘만 놓아 서비스의 콘텐츠(15개 지역)를 첫 화면에서 보여주지 못했다.

## 결정

세 가지를 규정한다. **(1) 추천 범위 = 거점 필수 + 지역 다중선택(옵션)** — 추천 입력에서 거점(Hub)은 여전히 필수로 받고, 사용자가 가고 싶은 지역을 0개 이상 선택할 수 있게 한다. 지역 0개 = 거점 주변 전체에서 코스 구성(기존 동작), 1개 = 그 지역 집중, 여러 개 = 선택된 지역들로 범위 한정. **(2) 홈 = 지역 카탈로그** — 홈을 히어로 + 15개 지역 그리드로 구성한다. 추천은 히어로의 버튼이, 지역은 그리드가 담당한다. 기존 진입 카드 2개(추천받기/지역 둘러보기)는 역할 중복으로 폐기. **(3) 거점별 지역 우선 정렬** — 거점을 고르면 그 거점과 가까운 지역(place.hubId 기준)을 지역 선택 목록 상단에 우선 표시한다. 위치 권한(geolocation)은 쓰지 않는다.

## 근거

① Hub-and-Spoke 근간 유지 — 지역 다중선택은 추천 범위를 좁히는 필터일 뿐, 거점 출발 전제를 깨지 않는다. ADR-003·모델·API recommend 구조를 갈아엎지 않음. ② 세 페르소나를 하나의 입력으로 커버 — 지역 미선택(P1 추천 의존), 1개(P3 슬로우 트래블), 여러 개(P2)가 선택 개수로 자연히 갈린다. ③ 위치 권한 없는 거점별 정렬은 place.hubId로 이미 가능한 고정 데이터 — 첫 진입 마찰(위치 팝업)을 피하면서 선택을 돕는다. ④ 카탈로그화로 첫 화면 시각적 밀도가 높아져 공모전 제출물 인상도 개선.

## 결과

① API recommend 요청에 regionIds[] (선택, 빈 배열 허용) 추가. ② 지역 1개 선택 시 그 지역 관광지가 코스를 채울 만큼 없으면 422 NO_COURSE_FOUND로 안내(기존 에러 경로 재사용, 새 처리 불필요). ③ 화면 구성 변경 — 지역 소개 화면(신규) 추가, 홈·추천 입력 개편(화면 설계서에서 반영). ④ 지역 소개 화면의 이 지역 코스 추천받기 버튼은 해당 지역이 미리 선택된 상태로 추천 입력으로 이동. ⑤ User Persona의 진입 경로 기술(대등한 두 카드)이 바뀌므로 점검.

## 대안

① 거점 없이 지역만으로 추천(지역 기반 재설계) — 거점 출발 대중교통 동선(P1)과 충돌하고 Hub-and-Spoke 근간을 무너뜨림 → 배제. ② 지역 선택 필수화 — 지역 모르는 P1에게 선택 부담 강요, 추천 의미 퇴색 → 옵션으로. ③ 입력+결과 한 화면 통합 — 결과가 무겁고(지도·동선) 공유 URL이 꼬임 → 입력(S3)·결과(S4) 분리 유지.
