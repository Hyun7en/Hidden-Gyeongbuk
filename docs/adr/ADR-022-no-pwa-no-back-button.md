# ADR-022 · PWA 미사용, 자체 뒤로가기 버튼 전면 제거

**상태** Accepted  
**작성일자** 2026-08-08

## 컨텍스트

SRS FR-W-04에 PWA(홈 화면 추가·정적 캐싱)가 우선순위 C로 들어있었고, ADR-002는 SPA 선택 근거로 "코스 공유 URL·PWA 요구"를 들었다. 화면 설계 과정에서 헤더 뒤로가기 버튼의 필요성을 검토하다가, PWA 여부가 이 판단을 가른다는 것을 확인했다 — PWA로 설치하면 브라우저 UI(주소창·뒤로가기)가 사라져 자체 뒤로가기가 필수가 된다. 확인 결과 **PWA는 의도한 적 없는 요구였고**, 실제로 원한 것은 화면 크기에 따른 반응형 동작이었다.

## 결정

① PWA를 채택하지 않는다(FR-W-04 폐기). 서비스워커·매니페스트를 두지 않는다. ② 그 결과로 **모든 화면에서 자체 뒤로가기 버튼을 제거**한다. 헤더는 로고 + 언어 선택기 + 다크모드 토글로 구성한다.

## 근거

① 일반 반응형 웹에서는 **브라우저 뒤로가기가 항상 존재**하므로 자체 버튼은 중복이다. ② 로고가 이미 "홈으로" 기능을 맡고 있어, 진입점이 단일한 화면에서도 목적지 표시 버튼을 둘 이유가 없다. ③ 자체 뒤로가기가 반드시 필요한 경우는 회원가입·결제 같은 **단계형 플로우**(브라우저 뒤로가기와 다른 의미를 가지는 경우)인데, 이 서비스엔 그런 플로우가 없다 — 추천 입력(S3)도 단일 폼이다. ④ 사용자가 설치해 재방문하는 유형의 서비스가 아니다 — 여행 중 검색으로 들어와 한번 보고 나가는 경로가 지배적이다.

## 결과

① SRS FR-W-04 폐기, In Scope에서 Out of Scope로 이동. ② **ADR-002의 SPA 선택 근거 중 "PWA 요구" 부분은 더 이상 유효하지 않다** — 다만 코스 공유 URL(FR-C-06)과 TypeScript 타입 안정성이라는 나머지 근거는 그대로여서 결론(React SPA)은 유지된다. ③ **뒤로가기 동작 검증은 프론트엔드 구현 단계로 이월된다** — Claude Design은 캔버스 렌더링 구조라 브라우저 히스토리와 연결되지 않아 프로토타입에서 검증할 수 없었다. **자체 버튼을 없앴으므로 브라우저 뒤로가기가 유일한 복귀 경로다** — 라우팅 적용 직후 반드시 확인한다. ④ 오프라인 대응은 브라우저 기본 캐시·서버 캐시 폴백으로 처리한다(User Persona §4 결론 8번 갱신).

## 대안

① PWA 유지 + 자체 뒤로가기 버튼 — 서비스워커 구현·캐시 전략·업데이트 처리 부담을 지므로 설치 수요가 불확실한 상태에서 받을 이유가 없다 → 배제. ② PWA는 안 하되 자체 뒤로가기는 유지 — 브라우저 기능과 중복되고 헤더 공간만 차지 → 배제. ③ 목록→상세 같은 일부 화면에만 목적지 표시형 뒤로가기("← 홈") 유지 — 검토했으나 로고와 기능이 겹쳐 중복 → 배제.
