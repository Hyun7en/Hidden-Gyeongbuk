# ADR-001 · TourAPI 데이터 수집 = 배치 적재

**상태** Accepted  
**작성일자** 2026-05-29

## 컨텍스트

TourAPI는 개발계정 기준 오퍼레이션별 일 1,000건 호출 제한과 응답 지연이 있다. 추천을 위해 15곳 데이터를 지역·카테고리로 필터링하고 가중치 점수를 계산해야 하며, 외부 API 장애 시에도 탐색·추천이 동작해야 한다.

## 결정

스케줄러가 TourAPI를 주기(일 1회) 호출해 정규화 후 MySQL에 적재한다. 사용자 요청은 적재된 데이터로만 처리하고, 요청 시 TourAPI를 실시간 호출하지 않는다.

## 근거

호출 제한을 회피하고, 캐시된 데이터 위에서 추천 계산이 빨라지며, 외부 장애와 무관하게 서비스가 유지된다.

## 결과

데이터 최신성은 배치 주기에 의존한다(축제 등 시기성 데이터는 주기 단축). 수집·정규화 배치 잡과 areaBasedSyncList2 증분 로직이 필요하다.

## 대안

요청 시 실시간 TourAPI 호출 — 추천 1회에 다수 호출이 발생해 지연·한도 초과 위험이 크고 외부 장애에 직접 노출되어 배제.
