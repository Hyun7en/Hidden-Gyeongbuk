# ADR-016 · 수집 파이프라인 = 언어별 독립 staging → Resolution → Merge

**상태** Accepted (ADR-014를 대체)  
**작성일자** 2026-07-30

## 컨텍스트

ADR-014의 수집 흐름은 국문 목록을 순회하며 각 건에 영문을 매칭하는 단방향 구조다. 이 구조에서는 EngService2에만 존재하고 KorService2에 대응 항목이 없는 장소가 순회 대상 자체에 들어오지 않아 **구조적으로 누락**된다. 외국인 관광객이 주 사용자인 서비스에서 영문 소스에만 있는 장소를 버리는 것은 손실이다. 또 일문·중문 등 언어를 추가하면 "국문 → 영문", "국문 → 일문" 식으로 매칭 경로가 언어 수만큼 늘어난다.

## 결정

수집을 3단계로 분리한다.

**(1) Staging** — 각 언어 서비스를 독립적으로 `areaBasedSyncList2`로 수집해 `staging_place`(lang 컬럼 보유 단일 테이블)에 원본 그대로 적재한다. 이 단계에서는 매칭·판단을 하지 않는다.

**(2) Identity Resolution** — staging 간 동일 장소 여부를 판정한다. 좌표 근접(1km 가드)을 1순위 키로, 이름 대조를 보조로 쓴다. 판정이 애매하면 quarantine으로 보낸다.

**(3) Merge** — 판정 결과에 따라 언어 중립 `place` 1건 + 언어별 `place_translation` 행으로 병합한다. 어느 한 언어에만 존재하는 장소도 place를 생성하고, 없는 언어는 번역으로 채운다.

## 근거

① **누락 제로** — 어느 언어 서비스에만 있어도 반드시 적재된다. ② **재현 가능** — 매칭 로직을 고쳐도 외부 API 재수집 없이 재매칭만 하면 된다(오퍼레이션별 일 1,000건 한도에서 큰 이점). ③ **언어 대칭** — 언어를 추가해도 매칭 경로가 늘지 않고 staging에 행만 늘어난다. ④ ADR-014가 확립한 이름+좌표 매칭 로직은 방향만 바꿔 그대로 재사용한다.

## 결과

staging 테이블이 추가되어 저장공간이 늘고, 배치가 수집·매칭 2패스로 분리된다. 매칭 키 우선순위가 이름 → 좌표에서 **좌표 → 이름**으로 바뀐다(이름 표기는 언어마다 다르지만 좌표는 언어 무관). 판정 실패 건은 place를 만들지 않고 quarantine에 남기며, 처리 방식(수동 검토/임계값 자동화)은 국·영문 실측 건수 확인 후 정한다 — 선제 자동화는 과잉이다. **오매칭보다 미매칭을 택한다**: 오매칭은 서로 다른 장소를 합쳐 잘못된 정보를 노출하고 탐지가 어려운 반면, 미매칭은 같은 장소가 둘로 쪼개질 뿐이고 사후 병합이 가능하다.

## 대안

① ADR-014 방식 유지 + 영문 전용 장소만 별도 처리 — 예외 경로가 생기고 언어 추가 시 예외가 언어 수만큼 늘어남 → 배제. ② staging 없이 메모리에서 양방향 대조 — 재매칭 시 외부 API를 다시 호출해야 하고 실패 건 관측이 어려움 → 배제. ③ 매칭 실패 시 자동으로 영문 전용 place 생성 — 오매칭이 곧 중복 place로 이어져 탐지가 어려움 → quarantine 채택.

## 후속 주석

**2026-08-17** — 본 ADR이 정한 **좌표 근접 가드 1km를 5km로 넓혔다.** 좌표를 1순위 키로 둔 판단 자체는 실측으로 확인됐고(이름이 일치하는 490쌍의 좌표 거리 중간값 0.00km, 절반 이상이 소수점까지 동일), 틀렸던 것은 "1km면 충분하다"는 가정이다. 반경별로 잡히는 쌍은 1km 467 / 2km 481 / 3km 485 / **5km 489** / 10km 490이었고, 놓친 것들은 죽계구곡 1.02km·영양 자작나무숲 1.40km처럼 아깝게 밖이었다. 관광공사가 같은 장소를 언어별로 등록할 때 찍은 점이 조금씩 다르다(주차장 vs 입구 등).

넓혀도 오매칭 위험이 낮은 이유는 **확정을 이름이 하기 때문**이다. 반경은 후보를 좁히는 역할일 뿐이고 국문명이 글자 단위로 완전히 일치해야 확정되며, 같은 이름이 여럿 걸리면 본 ADR의 "오매칭보다 미매칭" 원칙대로 quarantine으로 빠진다. 15개 지역 전체에서 동명 복수는 8건뿐이었다.

이 수정이 필요했던 이유는 **미매칭이 조용했다**는 데 있다. 가드 안에 후보가 하나도 없으면 quarantine이 아니라 "그 언어에만 있는 장소"로 판정해 place를 새로 만드므로, 같은 장소가 국문판·영문판 둘로 쪼개져도 보류 목록에 안 잡힌다. 본 ADR은 미매칭이 "사후 병합 가능"하다고 봤지만, 그건 미매칭이 **보이는** 경우에 한한 이야기다. 반경 밖 미매칭은 중복 place로 변해 눈에 띄지 않는다.

매칭 키 우선순위(좌표 → 이름)와 quarantine 방침은 그대로 유효하다. 재수집은 필요하지 않았다 — staging을 보존하는 설계 덕분에 `resolve?resetAll=true`로 재판정만 하면 됐고, 이것이 본 ADR 근거 ②가 실제로 값을 낸 첫 사례다.
