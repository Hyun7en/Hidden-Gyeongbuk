# ADR-005 · 캐시 = 인메모리 → Redis(확장)

**상태** Accepted  
**작성일자** 2026-05-29

## 컨텍스트

조회·추천 결과와 적재 데이터에 캐싱이 필요하나 MVP는 단일 인스턴스다.

## 결정

MVP는 애플리케이션 인메모리 캐시로 시작하고, 확장(다중 인스턴스) 시 Redis를 도입한다.

## 근거

단일 인스턴스에서는 인메모리가 가장 단순하고, Docker 환경이라 Redis 전환도 용이하다.

## 결과

다중 인스턴스 확장 시 캐시 일관성을 위해 Redis가 필요하다.

## 대안

처음부터 Redis 도입 — 단일 인스턴스 MVP에는 과하고 운영 부담이 증가 → 확장 시점으로 연기.
